## 本次更新内容摘要
- 新增 `GET /auth/microsoft` 与 `GET /auth/microsoft/callback`，支持管理员发起 Microsoft OAuth 授权并处理回跳。
- 使用签名且短期有效的 `state` 校验 OAuth 回调，并在失败时统一跳回微软邮箱列表页展示结果。
- 新增授权码换 token、读取 Graph `/me`、按邮箱 upsert 现有 `accounts` 记录的后端逻辑。
- 为 `accounts` 增加 `auth_type` 迁移字段，区分手动账号和 OAuth 账号。
- 在微软邮箱列表页增加“OAuth 登录”按钮、来源列，以及 OAuth 回跳结果消费逻辑。
- 补齐 `server/main.ts` / `server/runtime/env.ts` 对 `MS_CLIENT_ID`、`MS_CLIENT_SECRET`、`MS_TENANT_ID`、`MS_REDIRECT_URI` 的运行时注入。
- 在 `.env.example` 中加入 Microsoft OAuth 相关变量，并将回调地址固定为 `https://mail.aliyunus.0222999.xyz/auth/microsoft/callback`。

## 本次是否涉及配置变更
- 是
- 新增环境变量：`MS_CLIENT_ID`、`MS_CLIENT_SECRET`、`MS_TENANT_ID`、`MS_REDIRECT_URI`。
- 线上 `.env` 需要补充以上变量，并将 `MS_REDIRECT_URI` 设置为 `https://mail.aliyunus.0222999.xyz/auth/microsoft/callback`。
- 部署时需要将 `APP_IMAGE` 更新为固定 tag `ghcr.io/ywain-zh/microsoft-account-manager:2026.04.18-3`。

## 本次是否涉及数据结构/迁移
- 是
- 新增迁移 `migrations/0005_accounts_auth_type.sql`，为 `accounts` 表增加 `auth_type` 字段，默认值为 `manual`。
- 风险点是旧库首次启动时会执行该迁移；回滚代码前需确认数据库已兼容旧逻辑。
- 如需强制回滚到不识别 `auth_type` 的旧版本，应优先使用已验证兼容版本，避免直接切回过旧镜像。

## 风险说明
- 真实 OAuth 成功链路（微软登录、code 换 token、Graph `/me`、落库、读信）仍需要线上真实账号做完整冒烟。
- 本次新增环境变量若服务器 `.env` 未同步更新，OAuth 发起会返回 500 配置错误。
- 首次部署后需要重点观察 OAuth 回跳地址、授权失败提示、以及新老手动账号列表是否保持正常。

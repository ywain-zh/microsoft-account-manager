# RELEASE-2026-04-15-02

## 本次发布日期
- 2026-04-15

## 本次发布版本/tag
- `ghcr.io/ywain-zh/microsoft-account-manager:2026.04.15-2`

## 本次发布目的
- 将线上旧版 `microsoft-account-manager` 从基于 Wrangler 本地运行时的旧部署方式，切换到新的轻量自托管方案。
- 在切换前完成旧部署目录、旧数据目录、旧环境文件、旧容器信息和旧镜像信息的完整备份。
- 保证切换过程只使用固定 tag 镜像和轻量运行型命令，避免 2C2G 小机器因本机构建而卡死。

## 本次修改文件列表
- `.github/workflows/publish-image.yml`
- `releases/RELEASE-2026-04-15-02.md`

## 本次更新内容摘要
- 新增本次正式切换用的 release 文档。
- 新增 GitHub Actions GHCR 发镜像工作流，用于在 GitHub 远端构建并推送固定 tag 镜像，避免服务器本机构建。
- 固定本次上线镜像为 `ghcr.io/ywain-zh/microsoft-account-manager:2026.04.15-2`。
- 固定本次切换目录为 `/opt/microsoft-account-manager`，并明确要求保留旧部署目录 `/root/microsoft-account-manager` 作为回滚基础。
- 固定本次数据迁移方式为“只复制旧 D1 主库文件到干净的 `legacy-d1` 目录，再由新服务首次启动自动导入”。

## 本次是否涉及配置变更
- 是
- 新部署目录改为 `/opt/microsoft-account-manager`。
- 新环境文件改为 `/opt/microsoft-account-manager/.env`。
- 新部署使用 `APP_IMAGE=ghcr.io/ywain-zh/microsoft-account-manager:2026.04.15-2`。
- 新部署增加 `DB_PATH=/app/data/account-manager.db`、`LEGACY_DB_DIR=/app/data/legacy-d1`、`AUTO_IMPORT_LEGACY_DB=true`。

## 本次是否涉及数据结构/迁移
- 是
- 旧数据源仍为 SQLite，但不直接复用整个 Wrangler 数据目录。
- 本次迁移方式为复制旧业务主库 `.sqlite` 文件到新数据目录 `/opt/microsoft-account-manager/data/legacy-d1/legacy-import.sqlite`，由新服务导入生成 `/opt/microsoft-account-manager/data/account-manager.db`。
- 如果迁移前校验发现复制后的库缺少 `accounts` 或 `app_settings`，则必须立即停止部署并等待确认。

## 本次部署步骤
- 本次部署必须严格执行 `DEPLOY_LITE.md` 的标准流程和本次切换计划中已经固定的命令顺序。
- 先审查旧服务，再做完整备份，再预拉固定 tag 镜像，再停止旧服务，再准备新环境和数据迁移，最后执行 `docker compose pull` 与 `docker compose up -d`。
- 服务器禁止执行 `docker build`、`docker compose up -d --build`、`npm ci`、`npm install`、`npm run build`、`vite build`。

## 本次回滚方式
- 停掉新服务并移除新容器。
- 将重命名后的旧容器恢复为 `microsoft-account-manager`。
- 回到旧部署目录 `/root/microsoft-account-manager` 执行 `docker compose up -d microsoft-account-manager`。
- 保留 `/opt/backups/microsoft-account-manager-YYYYMMDD-HHMMSS/` 备份目录和新数据目录，先不删除，便于故障分析。

## 风险说明
- 本次切换包含旧 SQLite 数据导入到新数据目录的过程，重点风险是误选 `metadata.sqlite`；因此本次只复制旧业务主库文件，禁止直接挂载整个旧 D1 目录。
- 本次切换依赖固定 tag 镜像已提前发布到 GHCR；若镜像无法拉取，必须在停旧服务前中止流程。
- 本次 GHCR 发镜像依赖 GitHub Actions 和仓库 package 权限正常；如果 workflow 失败，必须先修正镜像发布，再继续服务器切换。
- 切换后需要重点观察登录、账户列表、微软邮箱读取、自建邮箱读取和健康检查是否正常。

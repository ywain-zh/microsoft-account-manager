## 本次更新内容摘要

### 缺陷修复：GLaDOS 账号无法保存
- 现象：账号类型选 GLaDOS、填好名称与 Cookie 后点「保存」，报「站点名称不能为空」，请求根本没有发出。
- 根因：具名插槽上直接写 `v-if` / `v-else-if` 会编译成 `DYNAMIC_SLOTS`，而 naive-ui 把插槽经 `NModal → BodyWrapper → NCard` 逐层转发，转发后的 footer 不会随 `accountKind` 更新，被冻结在弹框首次渲染时的那一份。`openCreateModal()` 先把 `accountKind` 置为 `public` 再打开弹框，因此 footer 恒为公益站版本，「保存」实际调用了 `submitAccount`，其客户端 `buildPayload` 立刻抛出公益站的校验错误。
- 佐证：切到「宝可梦」时两个 footer 条件均不成立、本应完全没有 footer，却仍渲染出带「保存」的公益站 footer。
- 修复：改为单个静态 `#footer` 插槽，条件下移到插槽内部（与弹框主体一致的写法），并在模板中加注释说明不可改回。宝可梦类型不渲染 footer 内容，用 `.n-card__footer:empty` 隐藏空容器。
- 同一缺陷的反向路径（GLaDOS 切回公益站）此前同样失效，一并修复。

### 新增：订阅链接 / 到期时间 / 流量额度
- 站点没有任何接口直接返回订阅链接与流量配额，二者均由 glados.cloud 前端自行拼接与映射。本次从站点前端 chunk 中还原了同样的算法：
  - 订阅链接：`https://update.glados-config.com/mihomo/{userId}/{code}/{port}/glados.yaml`，三段参数全部来自**已在调用的** `/api/user/status`，不新增站点请求。
  - 到期时间：`system_time` + `leftDays`，基于站点时间而非本地时钟。
  - 已用流量：新增调用 `/api/user/traffic`，取 `data.today` 字节，按 1 GiB 换算。
  - 套餐与流量额度：由 `/api/user/status` 的 `vip` 映射（0/10→Free 10GB、11→Edu 100GB、21→Basic 200GB、31→Pro 500GB、41→Team 2000GB、51→Enterprise 5000GB，其余 Basic 0GB）。
- 上述快照在签到、检测、余额刷新三条路径统一落库，取不到时以 `COALESCE` 保留旧值。
- 「检测」原先成功时不写库（失败时才写），导致点完检测列表不刷新；现改为成功时同步落库积分、剩余天数与新增字段，行为与失败路径对称。
- 列表展示：
  - 「余额」列改为三行：积分 / `剩余天数 · 到期日` / `已用 / 额度 GB`。列宽有限，到期日在同年时省略年份，完整日期保留在悬停提示中。
  - 「公告」列在 GLaDOS 行原本是固定的 `-`，现改为展示截断后的订阅链接 + 复制按钮，完整地址在悬停提示中。
  - 复制按钮复用全局样式类 `table-icon-button` 与项目通用复制图标，复制走既有的 `src/utils/clipboard.ts`。
- 新增 `src/components/icons.ts` 导出 `CopyGlyph`，与 `AccountsView.vue` / `CloudMailAccountsView.vue` 中现有的内联定义完全一致。既有两处本轮未改动，避免在带缺陷修复的版本里触碰无关视图。

## 风险说明
- **订阅链接是账号级凭据**，拿到即可直接使用该账号的代理配置。它必须在列表中明文展示才能复制，因此按明文存库；管理台整体已有登录鉴权，未登录访问相关接口返回 401。
- 订阅链接、套餐与流量额度的算法是从站点前端还原的，并非站点提供的公开契约；GLaDOS 前端改版可能导致链接模板或 `vip` 映射失效，需要同步调整。
- 站点 UI 把该流量标注为「本月已用」，但接口字段名为 `today`，本次按站点自身的展示行为照搬。
- 签到奖励值仍在成功时固定记为 `1`、重复签到记为 `0`（沿用上一版）。本次真实验证时账号当日已签到，仍未取得成功响应样本以确认 `points` 字段语义，故继续未做改动；该值只影响日志「奖励」列展示。
- 表格「公告」列由 `84px` 加宽至 `200px`，表格 `min-width` 由 `1120px` 提升至 `1240px`。1920 宽视口下无横向溢出；更窄的屏幕横向滚动距离会略微变长（该表格本就带横向滚动）。
- 每次签到会多产生一次 `/api/user/traffic` 请求；该请求失败已被捕获，不影响签到与兑换。

# Release 2026.05.26-5

## Image

- `ghcr.io/ywain-zh/microsoft-account-manager:2026.05.26-5`

## Scope

- Fix GPT JSON export fallback when Sub2API admin account records do not include token fields.
- Keep using the existing Sub2API admin search to locate the account ID, then read token credentials from the server-side `sub2api-postgres` database.
- Replace the container-internal `docker exec` CLI call with Docker Engine socket exec calls so the fallback is not blocked by an old Docker CLI API version.
- Clean non-JSON download errors so Cloudflare or HTML error pages are shown as short messages instead of full HTML.

## Cause

- The target GPT account data was still present in `sub2api-postgres`.
- The export failed because the app container's Docker CLI reported `client version 1.41 is too old` when trying to run `docker exec sub2api-postgres`.
- The Sub2API admin API returned the account but omitted token fields, so the database fallback was required.

## Config

- Update only `APP_IMAGE` in `.env` during deployment.
- No database migration is required.
- Existing `/var/run/docker.sock` mount is still required and already present in `docker-compose.yml`.

## Validation

- `npm run typecheck`
- `npm run build`
- Online read-only Docker socket exec probe confirmed `sub2api-postgres` can be queried without the old Docker CLI.

## Deploy

- Follow `DEPLOY_LITE.md`.
- Do not run `npm install`, `npm run build`, `docker build`, or `docker compose up --build` on the server.

## Rollback

- Set `APP_IMAGE=ghcr.io/ywain-zh/microsoft-account-manager:2026.05.26-4`
- Run `docker compose pull && docker compose up -d`

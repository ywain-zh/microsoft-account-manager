## 本次更新内容摘要

### dian115 浏览器登录降级（方案移植自 Automation Toolbox 的成熟过盾实现）
- **触发条件**：`performLogin` 的 HTTP 登录抛出 CF 拦截类错误（被 Cloudflare 拦截 / 人机验证失败 / 浏览器验证失败 / 响应格式无效）时自动降级；密码错误等业务错误不降级（浏览器登录同样会失败，避免白跑）。
- **浏览器登录流程**（`dian115_login_browser.py`，headless）：
  1. Camoufox headed 配置移植（`humanize=0.4` 贝塞尔鼠标轨迹、`block_webrtc`、`geoip=True` 按出口 IP 对齐时区/语言、Windows GPU 软化配置）；
  2. 访问 `https://m.dian115.com/login`，逐字符拟人化填写邮箱密码；
  3. 登录循环：轮询 `cf-turnstile-response`，未通过时**坐标点击** Turnstile 复选框（iframe 左侧 24px 垂直居中——新版 Turnstile 是 canvas 渲染无 checkbox DOM，DOM 点击不可靠；限频 3 秒防狂点被判机器），通过后点击登录；
  4. 检测到 `__Host-portal_token` cookie 即成功，stdout 输出 JSON 退出；密码错误类 toast 直接快速失败。
- **降级后**：拿到的新 token 落库（加密），签到/积分等业务请求继续走现有纯 HTTP 协议（browser-challenge → ECDSA browser-session → 签名请求），浏览器进程用完即退出不驻留。
- **超时与日志**：子进程 200 秒超时强制终止；Python 过程日志透传到主日志（`[Dian115BrowserLogin]` 前缀），便于线上排查过盾情况。

### Cloud Mail 管理员防删除保护（补提交，服务器已运行 3 天）
- 批量删除账号前先调 `/api/my/loginUserInfo` 校验管理员身份；管理员邮箱本身禁止删除，防止误删导致管理端失联。

## 风险说明
- **镜像体积**：795MB → 约 1.8~2GB（Camoufox 引擎约 1GB + Firefox 运行库 + pip 依赖）。服务器磁盘 20G 空余，部署后镜像占用约 2.8GB（当前 + 回滚），可接受；pull 时间变长（首次约几分钟）。
- **内存峰值**：浏览器登录为临时进程，峰值 +400~500MB、持续约 40 秒，平时不驻留（日常仍为 ~65MB）。服务器 1.6G 内存 / available 474Mi，登录瞬间偏紧；缓解：登录低频（token 约 24h 失效一次，每天 1~2 次）、串行执行、OOM 仅影响该次登录（下次签到自动重试）。若频繁 OOM 需考虑加 swap 或限制浏览器内存。
- **headless 过盾成功率**：本地实测 headless 一次通过；服务器出口 IP 与本机不同，CF 风控评分可能不同，首次真实运行需观察日志。若过盾失败会落明确错误信息到账号 `last_error`，不影响其他账号。
- **构建时间**：GHCR Actions 构建因新增 camoufox fetch 下载约 1GB，首次构建时间显著变长（约 10~15 分钟），tag push 后等待镜像就绪需耐心。

## 本次更新内容摘要
- 新增 GLaDOS 签到运行时：查询剩余天数 -> 签到 -> 查询积分 -> 按门槛兑换积分。
- 签到返回 `code 0` 记为成功、`code 1` 记为「今日已重复签到」同样计入成功、其余记为失败并标记账号异常。
- 积分兑换支持 `plan100 / plan200 / plan500` 三档，仅在启用兑换且总积分达到门槛时触发。
- Cookie 复用既有 `PUBLIC_CHECKIN_ENCRYPTION_KEY` 加密入库；列表接口不回传明文，仅独立凭据接口按需解密。
- 编辑账号时 Cookie 留空不覆盖原密文。
- 接入公益站定时调度：公益站签到完成后串行执行 GLaDOS 账号，账号间间隔 1 秒；GLaDOS 异常不影响公益站汇总通知发送。
- 运行结果并入既有 Telegram 签到汇总通知（复用 `PublicCheckinNotificationItem` 形状）。
- 出站请求复用系统代理配置 `system_proxy_config`；`302` 响应识别为登录失效并给出换 Cookie 提示。
- 公益站账号列表新增 GLaDOS 行，支持检测、签到、余额刷新、编辑、删除；「添加账号」弹框新增 GLaDOS 类型。
- 修复 `/api/public-checkin/glados/logs`：原实现把查询对象传给期望取值函数的参数且漏 `await`，接口实际返回空对象且服务端类型检查不通过。
- 日志接口对齐公益站日志契约：查询参数统一为 `accountId / status / startAt / endAt / limit / offset`，响应 `JOIN` 出 `accountLabel` 并补 `siteName`，前端表格列定义直接复用。
- 签到日志弹框新增「来源」筛选（公益站 / GLaDOS），两侧各自走服务端分页。
- 顺带修复既有缺陷：原先修改日志弹框的账号/状态/日期筛选器不会触发重新查询，现已改为筛选即时生效并回到第 1 页。
- 移除未被调用的死函数 `openCreateGladosModal`。

## 风险说明
- 签到奖励值当前在成功时固定记为 `1`、重复签到记为 `0`。参考实现是从签到响应的 `points` 字段读取本次获得积分，但该字段在不同版本可能表示账户总积分，本次验证时账号当日已签到、拿不到成功响应样本，因此未凭猜测改动。该值只影响日志「奖励」列展示，不影响签到、兑换与账号状态判定；待取得一次真实成功签到样本后再确认。
- 适配依赖 `glados.cloud` 当前接口协议（`/api/user/status`、`/api/user/checkin`、`/api/user/points`、`/api/user/exchange`）与 `token=glados.cloud` 签到参数，站点改版可能导致失败。
- 未实现参考项目中的 `railgun.info` 第二域名签到，本次仅覆盖 `glados.cloud`。
- Cookie 存在有效期，过期后接口返回 `302`，账号会被标记为异常并提示重新获取 Cookie，需要管理员手动更新。
- GLaDOS 出站请求复用系统代理配置，若代理不可用会导致签到失败，但已捕获异常且不影响公益站签到与其汇总通知。
- 定时调度中 GLaDOS 账号串行执行，账号数量较多时会延长单次调度耗时。
- 签到日志弹框的「来源」为二选一，没有「全部」混排选项：两张表各自服务端分页，混排无法给出语义正确的翻页与总数。如需混排需改为后端 UNION 查询，属后续可选优化。

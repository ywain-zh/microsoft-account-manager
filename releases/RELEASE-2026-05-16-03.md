- 发布日期：2026-05-16
- 来源分支：`dev`

## 发布目的

将 Cloud Mail 和微软邮箱的 GPT 有效检测状态持久化到数据库，并把 GPT 有效列改为可重复检测的刷新图标交互。

- `src/views/CloudMailAccountsView.vue`

## 更新内容

- 新增 `mail_gpt_validity_status` 表，按 `microsoft` 和 `cloud-mail` 分开保存邮箱 GPT 检测结果。
- 微软邮箱和 Cloud Mail 列表接口返回持久化的 `gptValidity` 状态。
- 手动 GPT 检测会带服务类型并写入数据库，刷新页面后仍保留检测结果。
- Sub2API 全量检测每个账号后，按邮箱匹配本地微软邮箱和 Cloud Mail 账号并同步 GPT 状态。
- GPT 有效列改为刷新图标交互：未检测为普通刷新，失败/缺失为红色刷新，有效为绿色 `GPT有效` 加刷新图标，所有状态都可再次检测。

## 部署步骤

1. 提交本次变更到 `dev`。
2. 推送 `dev`。
3. 创建并推送 tag `2026.05.16-3`。
4. 等待 GitHub Actions 构建并发布 GHCR 固定 tag 镜像。
5. 在阿里云服务器 `/opt/microsoft-account-manager` 备份 `.env` 和 SQLite 数据库。
6. 将 `.env` 中 `APP_IMAGE` 更新为 `ghcr.io/ywain-zh/microsoft-account-manager:2026.05.16-3`。
7. 执行 `docker compose pull` 和 `docker compose up -d`。
8. 检查容器状态、日志、资源占用和健康接口。

## 回滚方式

如需回滚，切回上一版已验证镜像：

```bash
cd /opt/microsoft-account-manager
sed -i "s#^APP_IMAGE=.*#APP_IMAGE=ghcr.io/ywain-zh/microsoft-account-manager:2026.05.16-2#" .env
docker compose pull
docker compose up -d
docker compose exec -T microsoft-account-manager wget -qO- http://127.0.0.1:8787/api/health
```

如需同时回滚数据库数据，可在停止容器后恢复部署前备份的 `data/account-manager.db.bak.2026.05.16-3`。
